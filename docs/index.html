Liquid Onton

Solid Onton got the upstream. Liquid Onton got the recessive commits. It supervises coding agents in isolated git worktrees, starts patches when their dependencies are ready, keeps pull requests in sync, reacts to CI and review feedback, and persists enough state to resume after a crash.

The plan

A plan contains only the information the executor consumes:

{
  "project": "safer-cache",
  "repository": "acme/service",
  "patches": [
    {
      "id": "cache-key",
      "goal": "cache keys include the tenant identifier",
      "dependsOn": [],
      "files": ["lib/cache_key.ml", "test/cache_key_test.ml"],
      "checks": [
        { "run": "dune exec test/cache_key_test.exe",
          "proves": "tenants cannot share cache entries" }
      ]
    }
  ]
}

Unknown fields, missing evidence, invalid paths, duplicate IDs, and dependency cycles are rejected before execution begins.

Run it

lo --plan plan.json
lo safer-cache

The first command starts a project. The second resumes it from its durable snapshot. See the repository README for installation, configuration, and operational details.
